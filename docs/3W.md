# Autogestión (SIU-Guaraní 3w) 3.23.0

El módulo **3w** (autogestión alumnos/docentes) se instaló como un tercer contenedor,
usando la **misma base de datos** que Gestión y siguiendo la
[guía oficial de instalación de 3w](https://documentacion.siu.edu.ar/wiki/SIU-Guarani/version3.23.0/instalacion/3w).

## Cómo se integró

1. Checkout SVN: `nodos/iupa/3w/trunk/3.23.0` → `./src-3w` (revisión 108274).
   Se hace con `scripts/03-svn-checkout-3w.sh`.
2. Imagen `Dockerfile.3w`: PHP 8.1 + Apache + extensiones (incluye **`intl`**, que exige
   `laminas/laminas-i18n`) + Composer 2. Las dependencias se instalan en el build.
3. El repo trae el script oficial `bin/docker-instalar`, que el entrypoint ejecuta en el
   primer arranque. Ese script:
   - instala dependencias,
   - copia `login_template.php` y los `docker-templates` a `instalacion/`,
   - reemplaza los placeholders de `config.php` y `alias.conf`,
   - da permisos y crea el symlink de Apache.
4. El entrypoint ajusta además:
   - `url_gestion` → Gestión,
   - `jasper_host`/`jasper_port` → `gestion:8081` (reutiliza el JavaBridge de Gestión,
     no hace falta levantar otro),
   - `captcha.activo = false` (no hay keys reCAPTCHA locales),
   - `url_identidad_genero` y `email_ayuda` (obligatorios en 3.23),
   - la clave de BD la reescribe porque el `sed` del script oficial rompe claves con `&`.
5. El alias de Apache queda en `/3w` (configurable) y se publica en el puerto **8091**.
6. En Gestión se agrega `url3w = "http://localhost:8091/3w"` a `instalacion.ini`, antes
   del bloque `[xslfo]`, como indica la documentación.

## Variables nuevas en `.env`

| Variable | Default | Uso |
|---|---|---|
| `W3_PORT` | `8091` | Puerto HTTP de Autogestión |
| `AUTOGESTION_ALIAS` | `/3w` | Alias de Apache dentro del contenedor 3w |
| `AUTOGESTION_UA` | `5` | Id de unidad académica del bloque de acceso `des01` |
| `AUTOGESTION_EMAIL_AYUDA` | `soporte@example.edu.ar` | Email de ayuda mostrado en la app |

> `AUTOGESTION_UA` debe corresponder a una unidad académica real dada de alta en Gestión
> (`negocio.sga_unidades_gestion`). El valor `5` viene del template Docker de SIU; en una
> base nueva no hay unidades cargadas, así que hay que crearla en Gestión o ajustar este
> valor. Para entrar también necesitás una persona con usuario/clave en Guaraní.

## Acceso

- Autogestión: http://localhost:8091/3w
- Gestión: http://localhost:8090/guarani/3.23

## Verificación

```bash
docker compose ps                                        # los 3 servicios healthy
curl -o /dev/null -w "%{http_code}\n" http://localhost:8091/3w/   # 200

# Test oficial de conexión a la base (bloque de acceso des01)
docker compose exec -T autogestion \
  sh -c 'cd /opt/guarani-3w/bin && ./guarani test_conexion des01'

# Ver los archivos generados
docker compose exec -T autogestion \
  sh -c 'ls -l /opt/guarani-3w/instalacion/{config.php,alias.conf,login.php}'
```

Resultado esperado del test: `SE CONECTO CON EXITO!!!!!!!!!` con
`dbname=guarani3`, `host=db`, `schema=negocio`.

## Comandos útiles

```bash
docker compose logs -f autogestion
docker compose restart autogestion
docker compose exec autogestion bash
docker compose up -d --build autogestion   # reconstruir solo 3w
```

Los archivos de configuración de 3w están en el volumen `guarani_3w_instalacion`, por lo
que sobreviven a `docker compose down` y a la recreación del contenedor.

## Producción

La guía oficial indica, solo para producción:

```bash
docker compose exec autogestion \
  sh -c 'cd /opt/guarani-3w/bin && ./guarani compilar_recursos'
```

y activar `'produccion' => true` en `instalacion/config.php`. En este armado el entrypoint
regenera `config.php` una sola vez (marcador `.docker-configurado`); si editás el archivo a
mano después, se conserva en el volumen.

## Reportes

No se levanta un JavaBridge propio: `config.php` apunta a `jasper_host = gestion`,
`jasper_port = 8081`. Eso funciona porque ambos contenedores comparten la red
`guarani_default`. Si separás 3w en otro host, revertí ese valor y levantá el bridge
según la documentación oficial.
